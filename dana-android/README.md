# DANA AI · دانا

دانا یک پروژهٔ **Android بومی با Kotlin و Compose** است. این پوشه از پنل Python همین مخزن مستقل است. [گزارش فارسی فاز صفر](docs/00-audit-fa.md) تصمیم‌های معماری، طرح اتصال ایران، مسیر OCR/TTS و درخت فایل‌ها را شرح می‌دهد.

## نسخهٔ ۰٫۱ چه دارد؟

- **خانه:** رابط فارسی RTL با Vazirmatn و گوی شیشه‌ای؛ مانیتور واقعی شبکهٔ پیش‌فرض Android. «اینترنت تأیید شده» نتیجهٔ بررسی سیستم‌عامل است، نه دسترسی به موتور هوش مصنوعی.
- **یادداشت آفلاین:** ساخت، ویرایش و حذف با تأیید. یادداشت‌ها با Room روی دستگاه حفظ می‌شوند. Room همچنین جدول‌ها و عملیات پایهٔ تاریخچهٔ مکالمه و حافظهٔ دستی را دارد؛ رابط چت و استخراج خودکار حافظه هنوز وجود ندارند.
- **حالت کاملاً آفلاین:** پیش‌فرض روشن، با تنظیم ماندگار DataStore. این نسخه در هیچ وضعیتی از برنامه درخواست شبکه نمی‌فرستد؛ خاموش کردن گزینه فقط ترجیح محلی را عوض می‌کند.
- **پروفایل BYOK:** ذخیرهٔ چند پروفایل برای قالب سازگار با OpenAI یا قالب بومی Gemini، با مدل، HTTPS Base URL و نشانگر وجود کلید. تغییر مقصد یک کلید موجود مستلزم وارد کردن کلید تازه یا حذف صریح آن است. افزودن، ویرایش و حذف پروفایل محلی است؛ نه تست اتصال، نه ثبت‌نام، نه ارسال درخواست.

### ثبت تنظیمات یک سرویس

۱. در «تنظیمات ← افزودن پروفایل» قالب API را مطابق مستندات سرویس انتخاب کنید. ۲. Base URL مستند سرویس و **شناسهٔ مدل** را وارد کنید. ۳. اگر سرویس به کلید نیاز دارد، در حساب خود کلید بسازید و فقط در فیلد «کلید API» قرار دهید. دانا کلید پیش‌فرض ندارد و دربارهٔ پلن رایگان یا دسترسی از شبکهٔ شما ضمانتی نمی‌دهد. پروفایل شبکهٔ محلی هم باید HTTPS با گواهی مورد اعتماد Android داشته باشد؛ `http://…` پذیرفته نمی‌شود.

### حفاظت از داده

- تنها مجوز صریح نسخهٔ فعلی `ACCESS_NETWORK_STATE` است؛ `INTERNET`، ضبط صفحه/صدا، Accessibility و نمایش شناور در این فاز فعال نشده‌اند. Cleartext و backup/انتقال دادهٔ اپ غیرفعال‌اند.
- کلید API با AES-256-GCM و کلید غیرقابل‌استخراج Android Keystore رمز می‌شود؛ nonce تازه برای هر بار ذخیره و AAD شامل شناسهٔ پروفایل، فرمت، نوع شبکه و Base URL است. ciphertext و تنظیمات پروفایل در یک تراکنش Room تغییر می‌کنند. UI فقط وجود کلید را نشان می‌دهد؛ فیلد ورود کلید پوشیده و دیالوگ آن `FLAG_SECURE` دارد.
- بدنهٔ یادداشت‌ها، تاریخچه و حافظه در فضای خصوصی اپ هستند، **نه** در یک DB رمزنگاری‌شده. حذف پروفایل کلید را در سرویس ارائه‌دهنده لغو نمی‌کند یا پاک‌سازی فیزیکی SSD را تضمین نمی‌کند. Clear app data داده‌های محلی دانا را پاک می‌کند؛ قبل از آن محتوایی را که نیاز دارید جداگانه نگه دارید.

## ساخت روی سیستم مجهز به Android SDK

پیش‌نیاز: **JDK کامل ۲۱**، Android SDK Platform 36 و Build Tools 36.0.0، و دسترسی به مخازن رسمی Gradle، Google Maven و Maven Central. حداقل دستگاه Android 8 / API 26 است. پوشهٔ `dana-android` را در Android Studio باز کنید و Gradle JDK را روی ۲۱ بگذارید. برای ابزار خط فرمان، `JAVA_HOME` و `ANDROID_HOME` را به مسیرهای محلی خود تنظیم کنید. اگر SDK از متغیر محیطی پیدا نمی‌شود، Android Studio می‌تواند `local.properties` را بسازد؛ آن فایل را commit نکنید.

```bash
cd dana-android
sdkmanager --licenses
sdkmanager 'platforms;android-36' 'build-tools;36.0.0' 'platform-tools'
./gradlew --no-daemon :core:domain:test :core:data:lintDebug :app:lintDebug :app:assembleDebug
./gradlew :app:installDebug                     # با گوشی یا امولاتور متصل
./gradlew :core:data:connectedDebugAndroidTest # آزمون واقعی Room، DataStore و Keystore
```

در Windows از `gradlew.bat` استفاده کنید. پس از `assembleDebug` موفق، APK در `app/build/outputs/apk/debug/app-debug.apk` قرار می‌گیرد. `:app:assembleRelease` نسخهٔ minified و بدون امضای انتشار می‌سازد. برای انتشار، امضا و تست روی دستگاه لازم است؛ هیچ keystore یا رمز انتشار در مخزن نیست.

Room برای صدور طرح پایگاه داده تنظیم شده است. اولین بیلد موفق، فایل واقعی `core/data/schemas/ai.dana.data.local.DanaDatabase/1.json` را می‌سازد؛ آن را بررسی و پیش از اولین تغییر schema ثبت کنید. ساختار ۱ در کد تعریف شده است و راهبرد destructive migration ندارد. Workflow مستقل `Dana Android` بیلد، lint و JVM test را روی GitHub Actions تعریف می‌کند؛ اجرای آزمون دستگاه جداست.

## چه چیزی واقعاً راستی‌آزمایی شده؟

| بررسی | نتیجه |
| --- | --- |
| هستهٔ دامنه | با Kotlin CLI 2.3.21 و `-jvm-target 17 -Werror` کامپایل شد. ۱۳ تست JUnit مربوط به URL/مقصد کلید، عدم افشای کلید و ورودی فارسی با JUnitCore 4.13 گذشت. اجرای CI از JUnit 4.13.2 کاتالوگ استفاده می‌کند. |
| بررسی محدود API اندروید | `AndroidNetworkMonitor.kt` و `KeystoreVault.kt` با کامپایلر CLI و JAR کامپایل API 36 از Sable type-check شدند. فایل‌های XML و مراجع کاتالوگ هم به‌صورت ایستا بررسی شدند؛ این بررسی معادل SDK Build یا اجرای Keystore نیست. |
| توزیع Gradle / بیلد کامل | هش JAR Wrapper با انتشار رسمی مطابقت داشت. دریافت توزیع Gradle در sandbox با خطای TLS پیش از Sync یا compilation متوقف شد. Android SDK کامل نصب نیست. |
| دستگاه و انتشار | ۶ آزمون instrumented نوشته شده‌اند ولی اجرا نشده‌اند. APK، تست رابط روی دستگاه، Room schema تولیدشده و نتیجهٔ CI در این تحویل وجود ندارند. |

معیار عبور فاز ۱: موفقیت لنت و debug/release build، تولید و بازبینی schema 1، اجرای تست دستگاه و تأیید دستی این موارد: ایجاد/ویرایش/حذف یادداشت پس از بستن اپ، ماندگاری حالت آفلاین، عدم نمایش کلید ذخیره‌شده، تغییر وضعیت شبکه بدون crash و چیدمان RTL روی دستگاه کوچک و با اندازهٔ فونت بزرگ.

**ادامه:** پس از عبور از معیار فاز ۱، فاز ۲ سیستم طراحی و صفحات پایهٔ مکالمه/تاریخچه را توسعه می‌دهد. استریم واقعی و `DanaAiRouter` در فاز ۳، گفتار و اکشن‌ها در فاز ۴، ثبت صفحه و OCR در فاز ۵ و حافظهٔ هوشمند در فاز ۶ می‌آیند.
