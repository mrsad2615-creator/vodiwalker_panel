# راهنمای موتورهای دانا · Studio ۰٫۳

دانا یک برنامهٔ اندروید بومی است. «میز کار» از موتورهای متنی انتخابی شما استفاده می‌کند. انتخاب نوع درخواست (پرسش، خلاصه، ترجمه یا پیش‌نویس) دستور همان درخواست را عوض می‌کند؛ گفتگو و تاریخچهٔ چندمرحله‌ای ایجاد نمی‌کند.

## Gemini · مسیر سریع

۱. در [Google AI Studio](https://aistudio.google.com/api-keys) با حسابی که شرایط استفاده از Gemini Developer API را دارد، کلید شخصی **Authorization / Auth key** بسازید؛ فایل حساب سرویس یا رمز حساب وارد نکنید. فقط داخل فیلد کلیدِ دانا وارد کنید، نه در چت، اسکرین‌شات یا URL. برای عرضهٔ عمومی، از کلید مشترک در APK استفاده نکنید.

۲. «تنظیمات ← راه‌اندازی Gemini» را باز کنید. نشانی `https://generativelanguage.googleapis.com/v1beta` از پیش تنظیم است. برای دریافت فهرست، حالت کاملاً آفلاین را خاموش کنید و «دریافت مدل‌ها از API» را بزنید. دانا با `x-goog-api-key` از `GET /v1beta/models` صفحه‌بندی‌شده استفاده می‌کند و مدل‌های دارای متد `generateContent` یا `streamGenerateContent` را نشان می‌دهد. عملیات فهرست‌خوانی پرامپت ندارد.

۳. یک **مدل خروجی‌متن** از فهرست انتخاب کنید یا شناسهٔ مستند آن را دستی بنویسید. فهرست، قبول‌شدن کلید برای خواندن فهرست است؛ تضمین تولید متن، سهمیهٔ رایگان، نوع خروجی یا پشتیبانی زبان نیست. «زمان دریافت فهرست» زمانی است که گوشی برای گردآوری فهرست سنجیده، نه پینگ شبکه یا سرعت تولید متن. بعد از ذخیره، در «مقایسه» موتور را انتخاب کنید و متن و مقصد را بازبینی کنید. تولید از `streamGenerateContent?alt=sse` با سقف ۱۰۲۴ توکن خروجی استفاده می‌کند؛ مدل‌های دارای استدلال ممکن است بخشی از بودجه را پیش از اولین متن صرف کنند.

**دسترسی و هزینه:** در تاریخ ۲۰۲۶-۱۱-۱۷ ایران در [فهرست رسمی مناطق Google AI Studio/Gemini Developer API](https://aistudio.google.com/docs/available-regions) دیده نشد. این پیش‌نمایش دسترسی یا هزینهٔ صفر را تضمین نمی‌کند. خطای `403` فقط به‌معنای غیرمجازبودن درخواست از دید میزبان است؛ دانا دلیل فیلترینگ را حدس نمی‌زند. در منوی آدرس سفارشی Gemini، کلید دیگری مخصوص همان میزبان وارد کنید و خط‌مشی سرویس را رعایت کنید. انتخاب این گزینه به ارائه‌دهندهٔ جایگزین ارسال خودکار نمی‌کند. برای انتشار سازمانی بهتر است سرویس مورد اعتماد خودتان کلید ارائه‌دهنده را سمت سرور نگه دارد.

## Apple · اتصال اختیاری به مدل روی مک

این قابلیت **Siri، Apple Account، iCloud یا Private Cloud Compute نیست**. طبق [مستندات Foundation Models اپل](https://developer.apple.com/documentation/foundationmodels)، مدل سیستم روی دستگاه سازگار اپل اجرا می‌شود و برای APK اندروید باینری یا REST مستقیمی ندارد. [همکاری اعلام‌شدهٔ اپل و گوگل](https://blog.google/company-news/inside-google/company-announcements/joint-statement-google-apple/) کلید Gemini را به مجوز Apple Intelligence تبدیل نمی‌کند. پل دانا فقط `SystemLanguageModel` اپل را با [SDK رسمی مک](https://github.com/apple/python-apple-fm-sdk/tree/v0.2.2) فراخوانی می‌کند؛ به موتور ابری یا موتور ساختگی تغییر مسیر نمی‌دهد.

### پیش‌نیاز مک و شبکه

- مک Apple silicon سازگار، **macOS 26 یا جدیدتر**، Xcode/SDK سازگار نسخهٔ ۲۶ یا جدیدتر (با پذیرش مجوز Xcode و انتخاب ابزار خط فرمانِ همان Xcode)، Python 3.11 یا جدیدتر به‌صورت arm64، Apple Intelligence فعال و مدل آماده. [راهنمای رسمی نصب SDK](https://apple.github.io/python-apple-fm-sdk/getting_started.html) ملاحظات سازگاری را دارد. مک باید هنگام استفاده روشن و پل در حال اجرا باشد.
- گوشی باید IP خصوصی مک را از شبکهٔ مورد اعتماد ببیند. پل را فقط بر یک IP خصوصی مشخص گوش دهید؛ روی روتر Port Forward تنظیم نکنید و سرور را عمومی نکنید. تنظیم محدودکنندهٔ فایروال برای شبکهٔ خودتان توصیه می‌شود. هیچ نیازی به فرستادن متن مک به Google نیست مگر در همان ارسال، Gemini را هم جداگانه انتخاب کرده باشید.
- نشانی HTTPS باید نامی داشته باشد که در **گواهی معتبر مورد اعتماد سیستم Android** درج شده و در DNS شبکهٔ خصوصی به آدرس مک برگردد؛ برای نمونه، نامی از دامنه‌ای که خودتان مدیریت می‌کنید، با گواهی از طریق تأیید DNS و رکورد محلی روی روتر. `mac.example.net` و `192.168.1.20` فقط مثال‌اند. دانا گواهی خودامضا یا نام ناسازگار را به‌صورت پیش‌فرض نمی‌پذیرد. اگر چنین HTTPS قابل‌اعتمادی ندارید، این مسیر را هنوز راه‌اندازی نکنید؛ TLS را حذف نکنید و شمارهٔ کارت، رمز یا دادهٔ شخصی را برای آزمایش مصرف نکنید.
- این نسخه رابط فارسی دارد؛ **پل مک دستور و پاسخ انگلیسی را هدف می‌گیرد**. متن فارسی یا زبان دیگری ممکن است توسط مدل رد شود. برای مقایسهٔ اولیه یک متن کوتاه انگلیسی انتخاب کنید. این اتصال روی LAN است، نه «اجرای مدل داخل گوشی»؛ حالت کاملاً آفلاین دانا آن را هم می‌بندد.

### اجرا

از پوشهٔ `dana-android/companion/apple-mac` روی خود مک:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt

BRIDGE_DIR="$HOME/.config/dana-apple"
(umask 077; mkdir -p "$BRIDGE_DIR"; set -C; .venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(48))' > "$BRIDGE_DIR/token")
```

اگر فایل `token` از قبل موجود است، دستور ساخت آن را بازنویسی نمی‌کند. فایل واقعی زنجیرهٔ گواهی TLS و کلید خصوصی همان گواهی را خارج از مخزن در این پوشه قرار دهید، طوری که کلید، فایل معمولی با دسترسی محدود به مالک (`chmod 600`)، و مالک آن حساب کاربری شما باشد. این گواهی و کلید، مجوز استفاده از مدل نیستند؛ برای TLS شبکهٔ خصوصی‌اند.

```bash
.venv/bin/python apple_bridge.py \
  --bind 192.168.1.20 --port 8765 \
  --cert "$BRIDGE_DIR/fullchain.pem" \
  --key "$BRIDGE_DIR/privkey.pem" \
  --token-file "$BRIDGE_DIR/token"
```

۱. IP مثال را با IP خصوصی واقعی مک جایگزین کنید. اجرا در پیش‌زمینه است؛ `Ctrl-C` سرویس را می‌بندد. بدون `--bind` فقط loopback در مک قابل‌دسترسی است.
۲. روی گوشی «تنظیمات ← اتصال به مدل اپل روی مک». آدرس پایه برای مثال `https://mac.example.net:8765/v1` است. توکن فایل خصوصی را مستقیماً در فیلد توکن بریزید؛ توکن را در URL یا چت ننویسید. مدل داخل اپ برای این پروتکل ثابت است و مدل اپل فقط روی مک اجرا می‌شود.
۳. «بررسی آمادگی مدل مک» درخواست احرازشدهٔ `GET /v1/models` می‌فرستد. گزارش آمادگی یعنی SDK آماده بودن مدل را اعلام کرده است، نه این‌که درخواست متن اجرا شده باشد. بعد از ذخیره برای آزمون عملی، یک درخواست ساده مانند `Summarize: The meeting is on Friday at 10 am.` را در میز کار فقط به مک ارسال کنید.

**عیب‌یابی:** `401` توکن را بررسی کنید؛ `503` با پیام مدل آماده نیست یعنی `SystemLanguageModel.is_available()` آماده بودن مدل را گزارش نکرده؛ در تنظیمات مک فعال بودن و دانلود Apple Intelligence را بررسی کنید. `429` یعنی پل یا SDK ظرفیت درخواست جدید ندارد؛ پل عمداً فقط یک درخواست را هم‌زمان پردازش می‌کند. خطای TLS را با بررسی نام میزبان و زنجیرهٔ گواهی اصلاح کنید، نه با غیرفعال‌کردن اعتبارسنجی. اگر توکن افشا شد، پل را متوقف کنید، توکن تازه بسازید، پل را دوباره اجرا و توکن پروفایل را عوض کنید.

## پروتکل و شواهد

- مسیر سفارشی OpenAI-compatible: آدرس پایهٔ HTTPS معمولا با `/v1`، `GET /models` در صورت پشتیبانی میزبان، و `POST /chat/completions` با SSE و `max_tokens`. نبود فهرست مانع وارد کردن دستی شناسه نیست.
- پل مک: HTTPS با حداقل TLS 1.2، Bearer token، بدون browser origin یا توکن query. `POST /v1/respond` متن، دستور و سقف خروجی را می‌پذیرد. پیام SSE فقط snapshot جایگزین‌شونده، پایان صریح یا کد خطای محدود دارد. از PyPI دو وابستگی مستقیم نسخه‌ثابت دارد: SDK اختیاری اپل و Hypercorn. SDK اپل در پردازش جداگانه اجرا می‌شود تا قطع اتصال یا اتمام مهلت، پردازش پل را آزاد کند. پل عمداً دسترسی عمومی، فایل، API ابزار، telemetry یا تاریخچهٔ گفتگو ندارد؛ پرامپت و پاسخ در کد پل لاگ یا ذخیره نمی‌شوند.
- آزمون‌های JVM اندروید از اتصال HTTPS و پاسخ‌های کنترل‌شدهٔ محلی استفاده می‌کنند. آزمون‌های پل روی Linux احراز هویت، TLS واقعی، سقف داده، SSE، آزادسازی پردازش و حالات خطا را بررسی می‌کنند؛ **آزمون تولید واقعی روی Mac و حساب واقعی Google انجام نشده است**. وضعیت «متصل» برای سرویس‌ها از وضعیت اینترنت Android یا وجود یک کلید استنباط نمی‌شود.
- اجرای هم‌زمان موتورهای مختلف همچنان به تأیید دقیق مقصدها وابسته است. دانا کلید را در Keystore به مقصد مقید می‌کند و تغییر نشانی، ارسال کلید قبلی به مقصد تازه را مسدود می‌کند. پاسخ تا زمانی که عمداً آن را به یادداشت منتقل و ذخیره نکرده‌اید، در حافظهٔ همان جلسه است؛ با «کپی متن» پاسخ را عمداً به کلیپ‌بورد سیستم می‌دهید.
