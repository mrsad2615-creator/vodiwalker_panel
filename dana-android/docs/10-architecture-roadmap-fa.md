# معماری هدف مرصاد · تصویر حرفه‌ای، صدای فارسی، اجرای امن فرمان

**وضعیت: طرح فنی برای نسخهٔ بعد، نه قابلیت‌های منتشرشده.** مبنا: [مرصاد ۰٫۹](09-mrsad-fa.md)؛ بررسی مستندات: ۱۷ نوامبر ۲۰۲۶. دامنهٔ اجرا: اپ عادی Android، نه اپ سیستمی، دستگاه روت‌شده یا سامانهٔ مدیریت دستگاه سازمانی.

**ترتیب تصمیم:** ابتدا حفظ داده، کیفیت خروجی و اجرای درست؛ سپس کاهش انتظار. تصویر حرفه‌ای اولین قابلیت محصولیِ این نقشه است. صدای سریع نباید موجب قطع جملهٔ کاربر، تلفظ بد، انتخاب موتور ضعیف‌تر یا اجرای فرمان با پارامتر حدسی شود.

## ۱. معماری فنی و تجربهٔ کاربر

```text
ANDROID · mrsad foreground UI

 Chat ── Local ─────── Room + bounded context ── LiteRT-LM (no network)
   └──── Online ────── final selected text ──────────────────┐
 Voice ─ mic/speaker ─ PCM and final transcript ─────────────┤
   └──── final transcript -> app -> Chat consent (text only)  │
 Image Studio ──────── Brief + approved image bytes ──────────┤
                                                             │
 Phone ─ user text / local ASR / opted-in transcript draft     │
     └─ LocalCommands -> CommandPolicy -> preview/confirm     │
         └─ DeviceActions -> Android API / Intent            │
         (no cloud-to-device executor)                        │
                                                             v
 ================= consent + exact route + payload + budget =================
                   MANAGED GATEWAY · no Android privileges
      Auth / entitlement -> signed catalog -> quota ledger -> adapters
                       /                |                      \
   Voice WSS <-> Azure Speech       Chat SSE/HTTPS         Image HTTPS + job
   audio <-> fa-IR text             OpenAI/Claude/         OpenAI Images /
   session buffers in RAM           Gemini (text out)     Gemini Image
                                                          encrypted temp TTL
```

| صفحه | مسیر عادی | گزینهٔ پیشرفته |
|---|---|---|
| **گفتگو** | «روی گوشی» بلافاصله فعال است. پس از یک ورود به حساب مرصاد در سرویس مدیریت‌شده، از «آنلاین» یک کارت مثل **GPT**، **Claude** یا **Gemini** را انتخاب کن؛ انتخاب مستقل از تصویر به خاطر سپرده شود. | «تحلیل چندموتوره»، کلید شخصی و جزئیات مدل در تنظیمات، نه جلوی کادر پیام. |
| **تصویر** | «ساخت» یا «ویرایش»، توضیح فارسی، نسبت تصویر و در صورت نیاز مرجع؛ یک موتور «پیشنهادی» با **نام واقعی و کیفیت استودیو**. پیش‌نمایش هزینه/تعداد قبل از ارسال. | «موتور دیگر»، ماسک، لایهٔ متن، مقایسهٔ دو خروجی و ابعاد چاپ، فقط وقتی مسیر انتخابی پشتیبانی می‌کند. |
| **فرمان** | دکمه‌های صریح گوشی یا «بگو/بنویس»؛ برای عملِ تغییردهنده، پیش‌نمایش و تأیید فارسی. | انتخاب دستیار پیش‌فرض یا اتصال رسمیِ یک برنامه، هر کدام با دسترسی جدا. |

**معنای «آماده»:** کاتالوگ مدیریت‌شده پس از استقرار و یک ورود، بدون ورود کلید برای تک‌تک مدل‌ها. پشت هر کارت، حق استفاده، منطقهٔ مجاز، سهمیه، اعتبار و تست زندهٔ همان مسیر لازم است. حساب ایمیلی فعلی به‌تنهایی اعتبار API نمی‌دهد. کارتِ فاقد دسترسی، دلیل واقعی و «اتصال/بررسی دسترسی» نشان می‌دهد، نه «آماده». مدل‌های محلی همچنان بدون حساب کار می‌کنند. OpenRouter Free مسیر جدا با سقف قیمت صفر است؛ هیچ‌گاه بی‌صدا به مسیر پولی یا به سرویس دیگر منتقل نمی‌شود.

هر `RouteCatalog` شامل `provider + modelId + api + region + modalities + verifiedFeatures + retention + rateCard + revision + checkedAt + expiresAt` است. در کاتالوگ قابلیت «انتخاب» با capability «این حساب می‌تواند تصویر/ادیت بسازد» یکی نیست. دسترسی با نمونهٔ غیرحساسِ مجاز و بررسی خروجی و هزینه تأیید می‌شود. پیش از تغییر مدل، endpoint یا شرایط داده، کارت غیرفعال/نیازمند تأیید شود. اگر snapshot رسمی موجود نیست، ID دقیق + تست رگرسیون دوره‌ای؛ بدون alias شناورِ `latest` و بدون قرارداد preview به‌عنوان مسیر اصلی. [AvalAI](https://docs.avalai.ir/en/news/2026-11-11-claude-fable-5-2-gemini-4-carbon-gpt-image-2-6-added) می‌تواند **مسیر مستقل** و اختیاری برای حساب مجاز باشد؛ فهرست قابلیت‌ها، نگه‌داری و هزینه‌اش از upstream به ارث نمی‌رسد.

**قرارداد مرز سرور:** `GET /v1/catalog` فقط متادیتای مدل؛ `POST /v1/chat/turn` → SSE برای متن؛ `WSS /v1/speech` با نشست کوتاه و فریم اندازه‌محدود، جدا از چت؛ `POST /v1/image/jobs` با `Idempotency-Key` → شناسه و وضعیت؛ `GET /v1/image/jobs/{id}` برای بازیابی و مسیرِ جدا برای لغو. هر ارسال به `routeId + catalogRevision + scope + limits` و خلاصهٔ payload مصوب بسته می‌شود؛ digest بایت‌های مرجع پس از آماده‌سازی محاسبه شود. گیت‌وی خودش مدل، حق استفاده، مهلت و سقف را دوباره کنترل می‌کند. `429`، `payment_required`، `model_unavailable` و `content_blocked` حالت‌های صریح UI‌اند؛ هیچ API عمومی برای اجرای فرمان وجود ندارد.

**هم‌زمانی با هدف مشخص:** مسیر عادی یک موتور دارد. حالت «تحلیل پروژه» با اجازهٔ صریح دو موتور را روی Brief محدود و یکسان، با نقش‌های «پیشنهاد» و «بازبینی مستقل» اجرا می‌کند؛ فرض‌ها و اختلاف‌ها کنار هم می‌آیند، نه رأی‌گیری برای اعلام حقیقت. ترکیب آنلاین یک درخواست جدا با مقصد و هزینهٔ مشخص است. مقایسهٔ تصویر هم حداکثر دو کار هم‌زمان، یک خروجی در هر موتور و دو مقصدِ نام‌برده؛ انتخاب و چاپ نهایی با کاربر. هیچ‌یک از موتورهای موازی به Phone، فهرست برنامه‌ها یا حافظهٔ خصوصی دسترسی ندارد.

## ۳. استودیوی تصویر؛ معیار اصلی خروجی قابل استفاده است

1. **Brief قابل ویرایش.** پرامپت فارسی حفظ شود؛ فیلدهای کم‌تعداد: *موضوع و تعداد، نسبت/قاب، سبک و نور، جزئیات الزام‌آور، چیزهایی که نباید تغییر کنند، متن عیناً، نقش هر عکس مرجع*. قالب‌های «عکس محصول»، «پوستر فارسی»، «پرتره» و «ویرایش زمینه» همین مدل را پر کنند. اگر بازنویسی با مدل متنی فعال شد، قبل از ارسال تغییرات را نشان بده؛ اسم برند، رنگ و متن را بی‌اجازه عوض/ترجمه نکن. عکس مرجع برای نویسندهٔ پرامپت لازم نیست و پیش‌فرض به آن ارسال نمی‌شود.
2. **آماده‌سازی محلی مرجع.** Photo Picker/SAF؛ یک تا سه مرجع در فاز اول با عنوان «سوژه/سبک/ترکیب‌بندی». پیش‌نمایش عکس‌های ارسالی، MIME و امضای فایل، ابعاد، چرخش EXIF، سقف تعداد/مجموع پیکسل و بایت **پیش از decode کامل**؛ حذف GPS/EXIF خصوصی از کپی ارسالی، نه از فایل اصلی. برش یا کاهش اندازه تنها با پیش‌نمایش و تأیید؛ نبود قابلیت روی موتور منتخب یعنی آن گزینه غیرفعال است. [Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker)
3. **رندرِ نسخه‌دار.** `ImageJob` به مدل/سرویس/نسخهٔ کاتالوگ، ورودی مصوب، نسبت/اندازه، کیفیت، عملیات و `maxCost` بسته شود. برای OpenAI مسیر generation/edit واقعی، برای Gemini تنها پاسخ تصویری قابل قبول انتخاب شود؛ متن، بخش intermediate/thought یا پاسخ ۲۰۰ بدون تصویر، خروجی موفق نیست. کیفیت استودیو پیش‌فرض است؛ «طرح اولیه» انتخاب جداست. اگر داده یا تعرفهٔ دقیق برای برآورد سقف موجود نیست، ارسال نکن. بدون grounding وب یا ارسال به داور دیگر به‌صورت پیش‌فرض. پیش از ارسال تصویر افراد، حق استفاده و رضایت روشن باشد؛ ردشدن طبق سیاست سرویس، retry یا تعویض موتور برای دورزدن نمی‌سازد.
4. **ادیت کنترل‌شده.** یک تغییر در هر نسخه؛ مرجع و ماسک روی دستگاه و خروجی قابل مقایسه با قبل. ماسکِ مدل راهنماست، نه قفل پیکسل؛ فقط قابلیت تست‌شدهٔ هر API فعال شود. برای «برچسب یا لوگو تغییر نکند» از لایهٔ پیکسلی محافظت‌شده و ترکیب محلی روی بوم هم‌تراز استفاده کن؛ اگر هم‌ترازی/حافظه و حفظ ناحیه قابل احراز نیست، گزینهٔ قفل قطعی ارائه نده. [2](https://developers.openai.com/api/docs/guides/image-generation)
5. **متن فارسی بدون اتکا به املای مدل.** مدل پس‌زمینهٔ بدون نوشته و فضای مناسب بسازد. تیتر/قیمت/شمارهٔ تماس با متن عیناً، فونت مجاز، چیدمان native با RTL، نیم‌فاصله و شکست خط به‌صورت **لایهٔ مستقل** رندر شود. کنترل کنتراست، خروج از قاب و پیش‌نمایش ۱۰۰٪. نمونه: «محصول نقره‌ای، زمینهٔ سرمه‌ای؛ لوگوی مرجع ثابت؛ تیتر `ساعت‌های آبان` روی لایهٔ محلی». فایل خام مدل و خروجی پوستر دو فایل متمایزند.
6. **کار پایدار، خروجی اصلی.** حالت‌ها: `accepted → rendering → ready | failed | cancel_requested | unknown`. فقط job ID و وضعیت را پس از بستن صفحه بازیابی کن؛ retry وضعیت مجاز است، اما تولید پولی دوباره نه. رزرو اتمیک سقف، کلید idempotency در گیت‌وی به‌ازای حساب و payload، و ارسال مجدد فقط وقتی قرارداد سرویس عدم ارسال/تکرار مطمئن را ثابت کند. در timeout پس از ارسال: «وضعیت نامشخص؛ ممکن است هزینه ثبت شده باشد»؛ پیش از تلاش جدید تأیید بگیر. `cancel` روی گوشی حتماً انتظار را متوقف می‌کند؛ توقف رندر/صورتحساب فقط با تأیید سرویس. خروجی PNG/JPEG اول، جریانی و محدود به سقف مشخص هر مدل؛ تصویر بندانگشتی کم‌حافظه و export بایت اصلی با SAF. اندازه/تعداد پیکسل و سقف decode از قرارداد مدل و تست حافظهٔ گوشی استخراج شود؛ 4K فقط زمانی عرضه شود که پیش‌نمایش و خروجی اصلی بدون OOM پایدارند. نسخهٔ ادیت‌شده جدا، بدون حذف عمدی نشان منشأ سرویس؛ SVG فعال، لینک دانلود دلخواه و decode بی‌سقف پذیرفته نشوند.

**دروازهٔ کیفیت:** مجموعهٔ ثابت حداقل ۱۲۰ Brief فارسی با دادهٔ مجاز (محصول چندمرجعی، پوستر، پرترهٔ رضایت‌دار، نسبت عمودی، ماسک و حفظ جزئیات). دو ارزیاب کور، امتیاز *وفاداری به قیود، ترکیب، عیوب بصری و قابلیت انتشار* و داوری سوم برای اختلاف. هدف اولیه: ≥۸۵٪ از **اولین خروجی‌های کیفیت استودیو** قیود الزامی را رعایت کنند و امتیاز قابلیت استفاده ≥۴ از ۵ بگیرند؛ امتیاز هر دسته و هزینهٔ هر خروجی قابل استفاده جدا منتشر شود. لایهٔ تایپ فارسی و پیکسل‌های قفل‌شدهٔ محلی باید در همهٔ آزمون‌های ثابتِ مربوط دقیق بمانند؛ ۲۰۰ HTTP یا 4K بودن، قبولی بصری نیست. معیار با خروجی واقعیِ حساب مجاز سنجیده می‌شود، نه با نمونهٔ تبلیغاتی یا فقط fixture.

## ۴. خط لولهٔ NLP و گفتار فارسی

- **ورودی و نوبت:** لمس میکروفون در صفحهٔ حاضر، نشان ضبط، `AudioRecord` با PCM16 little-endian تک‌کاناله 16 kHz و قطعات حدود ۲۰–۴۰ ms؛ حداکثر ۳۰ ثانیه/نوبت در پایلوت. مسیر WSS احرازشده به Azure Speech SDK با `fa-IR`. نتیجهٔ جزئی فقط برای زیرنویس، نتیجهٔ نهایی برای تصمیم. خاموشی میکروفون بعد از نوبت، لغو، قطع شبکه، خروج از صفحه یا از دست رفتن تمرکز صوتی. [1](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support) [1](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-use-audio-input-streams)
- **فهم فارسی:** متن اصلی برای نمایش و نام خاص حفظ شود؛ کپی جدا برای نرمال‌سازی `ی/ي`، `ک/ك`، رقم‌های فارسی/عربی، نیم‌فاصله و «نیم ساعت/یک ربع». نام‌های انگلیسی، اعداد سریال و تلفظ نام کاربر بازنویسی حدسی نشوند. برای فرمان، اول نوع و فیلدهای مجاز؛ «هفت و نیم» بدون صبح/عصر سؤال تکمیلی می‌خواهد. تاریخ و زمان به منطقهٔ زمانی دستگاه و تاریخ مرجع زمان تأیید بسته شوند. تقویم شمسی فقط بعد از تست تبدیل تاریخ معتبر. دیکتهٔ آنلاینِ فرمان رضایت جدا دارد و فقط پیش‌نویس می‌دهد؛ ASR یا مدل فرمان اجرا نمی‌کند.
- **مدیریت زمینه:** همان موتورِ انتخاب کاربر فقط متن این نوبت و بخش محدودی از گفتگو **با هم‌منشأ و رضایت یکسان** می‌گیرد. ASR متن را به اپ برمی‌گرداند؛ لایهٔ اجازه در اپ پیش از درخواست LLM اعمال می‌شود. تغییر موتور، ارسال تاریخچه، ضمیمه یا محتوای محلی به صورت پیش‌فرض بسته است؛ کاربر می‌تواند متن مشخص را مرور و برای مقصد جدید انتخاب کند. حافظهٔ عادت‌ها محلی/اختیاری و قابل پاک کردن؛ نوشتن آن از خروجی مدل خودکار نیست.
- **خروجی:** جریان پاسخ واقعی را در مرز جمله/عبارت قابل فهم به TTS بده، نه توکن‌به‌توکن و نه با جملهٔ پُرکننده. `fa-IR-DilaraNeural` و `fa-IR-FaridNeural` نامزد انتخاب صدا هستند؛ قابلیت منطقه و نام/عدد با آزمون زنده. برای اعداد، تاریخ، واحد و واژهٔ وام‌گرفته نسخهٔ خواندنی جدا بساز؛ SSML فقط تولیدِ کد خودمان با escape، بدون تگ، URL یا صدای سفارشی از متن مدل. پخش جریانی، Audio Focus، قطع پاسخ با دکمه همیشه؛ قطع با گفتار فقط روی دستگاهی که AEC را در آزمون گذرانده و در نشست فعال. نسل نوبت قبلی حق پخش یا اجرای بعد از لغو ندارد. [1](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-lower-speech-synthesis-latency) [ماتریس صدا](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support#text-to-speech)
- **آفلاین و خطا:** `createOnDeviceSpeechRecognizer` از API 31 تنها اگر تشخیص محلی و مدل فارسی واقعاً در دسترس باشد؛ قابلیت‌سنجی API 33 در صورت امکان. TTS محلی تنها با صدای نصب‌شدهٔ بدون شبکه. اگر وجود ندارد، ورودی/خروجی متنی باقی می‌ماند؛ هیچ انتقال خودکار به موتور صوتی شبکه یا دانلود در پس‌زمینه. [1](https://developer.android.com/reference/android/speech/SpeechRecognizer)

## ۵. راهبرد کاهش تأخیر و روش اندازه‌گیری

اتصال WSS و Speech/TLS را پس از ورود آگاهانه به جلسهٔ صوتی گرم و در همان جلسه بازاستفاده کن، **نه قبل از رضایت**. capture، دریافت زیرنویس و آماده‌سازی UI موازی؛ مدل فقط پس از نتیجهٔ نهایی ASR. پخش اولین عبارت کامل روی بافر کوچک تطبیقی با backpressure؛ در ازدحام سرریز صدا را به خطای قابل فهم تبدیل کن، نه حذف پنهانی کلمه. صف تصویر و نشست صدا ظرفیت، timeout و thread/dispatcher جدا دارند. کش بدون متن شخصی برای کاتالوگ/قالب، نگه‌داشتن تاریخچهٔ محدود و حذف round-tripهای غیرضروری، نه افت کیفیت. اگر موتور عمیق دیرتر است وضعیت واقعی و «توقف» نشان بده؛ به مدل دیگر عوض نکن.

| نقطهٔ شروع ← پایان | هدف p50 | هدف p95 | تعریف |
|---|---:|---:|---|
| لمس ضبط ← اولین نمونهٔ قابل دریافت | ۱۰۰ ms | ۲۵۰ ms | مجوز از قبل داده شده؛ پنجرهٔ مجوز جدا اندازه‌گیری شود. |
| آخرین واج کاربر ← متن نهایی ASR | ۵۵۰ ms | ۱٬۰۵۰ ms | شامل پایان‌دهی گفتار و شبکه؛ تمایز مکث طبیعی با پایان نوبت. |
| متن نهایی و ارسال مجاز ← اولین عبارت کامل پاسخ | ۵۵۰ ms | ۱٬۴۰۰ ms | نشست گرم، پروفایل مکالمه، متن کوتاه؛ اولین توکن معادل عبارت نیست. |
| عبارت کامل ← اولین صدای شنیدنی | ۲۵۰ ms | ۶۵۰ ms | TTS + شبکه + صف پخش؛ نه فقط اولین بایت در سرور. |
| **آخرین واج ← اولین پاسخ شنیدنی** | **۱٫۵ s** | **۳٫۵ s** | هدف سر‌به‌سرِ مستقل برای مکالمهٔ معمولیِ گرم؛ شروع سرد جدا با هدف p95 ≤۵s. این عدد جمع صدک‌ها نیست. |
| توقف/قطع کاربر ← سکوت پخش قبلی | — | **۲۰۰ ms** | توقف محلی، مستقل از پاسخ لغو سرور. |
| متن نهایی در حالت فرمان ← پیش‌نمایش معتبر | — | **۱۵۰ ms** | پردازش محلی؛ شبکه و خواندن برنامه‌های دیگر در مسیر نیست. |
| لمس تأیید ← تحویل به API/Intent | — | **۷۵۰ ms** | زمان کاربر و مدت انجام کار در برنامهٔ مقصد جداست. |

این اعداد **اهداف پذیرش، نه اندازه‌گیری فعلی** هستند. روی حداقل یک گوشی میان‌ردهٔ ARM64 و یک گوشی دیگر از OEM متفاوت، Wi‑Fi و LTE/5G را جدا گزارش کن: گرم/سرد، بلندگو/هدست، RTT تا گیت‌وی ≤۱۰۰ ms و شبکهٔ ضعیف نیز جدا. با زمان یکنواخت دستگاه و لاگ فقط نقاط زمانی `endOfSpeech/asrFinal/firstPhrase/firstAudible/cancel`؛ خروجی شنیده‌شده با loopback آزمایشگاهی روی صدای مجاز نمونه‌گیری شود. دست‌کم ۲۰۰ نوبت در هر پروفایل اصلی؛ صدک، نرخ شکست/timeout، درصد جملهٔ بریده و فاصلهٔ پخش گزارش شوند، نه حذف timeoutها از نتیجه. برای تصویر زمان پذیرش کار p95 ≤۲s پس از **تکمیل آپلود**؛ زمان رندر، دانلود و decode جدا ثبت شوند، کیفیت نهایی برای این عدد پایین نیاید.

**کنترل کیفیت صدا:** حداقل ۳۰۰ جملهٔ خوانده/تعاملی از ≥۱۲ گویندهٔ رضایت‌دار، فارسی محاوره، مکث، عدد و ساعت، فارسی–انگلیسی، نویز و لهجه در زیرگروه جدا. هدف WER پس از نرمال‌سازی ≤۱۲٪ در سکوت و ≤۲۲٪ در نویز معمول؛ درستی *هم‌زمانِ قصد و همهٔ فیلدهای فرمان* ≥۹۸٪ در سکوت/≥۹۵٪ در نویز؛ هیچ اجرای بی‌تأیید در مجموعهٔ ایمنی. نرخ سؤال تکمیلی و دقت اعداد جدا گزارش شوند. برای TTS میانگین امتیاز طبیعی‌بودن ≥۴/۵ در شنیدن کور و صحت خواندن مقادیر حساس در fixture؛ عدم قبولی یعنی بهبود مسیر یا محدود کردن عرضه، نه فرض «پشتیبانی فارسی = کیفیت بالا».

### مرز اعطای اختیار

در گفتگو، تشخیص جملهٔ امری فقط می‌تواند دکمهٔ «باز کردن در فرمان» نشان دهد. با لمس آن **متن نوبت خود کاربر** وارد پیش‌نویس می‌شود، نه دستورِ تولیدشده توسط مدل. مثال: «یه تایمر دو دقیقه و نیم بذار» → «تایمر: ۲ دقیقه و ۳۰ ثانیه؛ باز کردن ساعت» → تأیید → تحویل ۱۵۰ ثانیه به ساعت. «تایمر نذار» یا «تایمر دو» به اجرا تبدیل نمی‌شود.

```text
Explicit Phone entry -> parse user input -> CommandProposal(type, typed slots)
    -> reject / clarify / show exact Android effect
    -> visible UI approval bound to action + target + values + current session
    -> AuthorizedAction (single use, short expiry, app-internal)
    -> recheck unlock + permission + handler + current lifecycle -> execute once
    -> Denied | Unavailable | HandedOff | Applied (only if verifiable)
```

- **شبکه فقط داده می‌دهد، نه اختیار.** نام operation از enum کامپایل‌شده، بدون Intent/URI/کد عمومی به انتخاب مدل. دادهٔ OCR، وب، ایمیل، پیام Share، متن تولیدی و ASR جزئی نمی‌توانند درخواست مجاز بسازند. برای فرمان صادرشده از دیکتهٔ آنلاین، فقط متن وارد پیش‌نویس می‌شود؛ تأیید باید روی UI و خارج از کانال مدل/صدا ثبت شود. نام پرونده، شماره، مدت و اثر روی دستگاه نشان داده شود؛ تغییر هر فیلد، ترک صفحه، قفل، مهلت کوتاه یا بازنشانی فرایند، تأیید را باطل می‌کند. replay/double tap نباید عمل را تکرار کند. در عملیات با نتیجهٔ نامشخص retry خودکار نداریم. پایلوت فقط یک عمل در هر نوبت؛ زنجیره‌کردن کارها در نسخهٔ بعد فقط با مراحل allowlist، پیش‌نمایش همهٔ آثار و توقف در نخستین نتیجهٔ نامشخص.
- **حریم خصوصی جدا برای متن، صوت و عکس.** نخستین استفادهٔ آنلاین و هر تغییر مقصد/نوع داده، نمایش دادهٔ ارسالی، مدت نگه‌داری و هزینهٔ احتمالی. دکمهٔ توقف شبکه، نشست/صف در حال ارسال را لغو یا مسدود می‌کند؛ در «کاملاً آفلاین» هیچ فراخوان AI، دانلود صوت یا ارسال معوق؛ فعال‌کردن آنلاین انتخاب مجدد است. آرشیو محلی از دیتای آنلاین جدا؛ فایل/URI و فهرست نصب‌ها به‌طور پیش‌فرض از گوشی خارج نمی‌شوند. صوت خام در اپ و گیت‌وی فقط بافر RAM نشست؛ لاگ payload، ضبط باگ، SSML/رونوشت پیش‌فرض خاموش. Azure نحوهٔ پردازش real-time را جدا از Batch مستند کرده؛ تنظیم و قرارداد همان Resource بررسی شود. [2](https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/speech-service/speech-to-text/data-privacy-security)
- **ذخیرهٔ موقت تصویر شفاف.** طرح اولیه: فایل ورودی/Brief رمزگذاری‌شده تا پایان ارسال به موتور یا حداکثر ۳۰ دقیقه؛ نتیجهٔ دریافت‌نشده حداکثر ۲۴ ساعت، با پاک‌سازی بعد از دریافت/حذف کار و بدون bucket عمومی یا نسخهٔ پشتیبان محتوا. آرشیو دائم فقط محلی با انتخاب کاربر. زمان‌بندی TTL داخل مرصاد است، نه وعدهٔ حذف کپی نزد عرضه‌کننده. `store=false` در APIهای پشتیبانی‌شده ≠ Zero Data Retention؛ استثناهای abuse monitoring و سیاست هر پروژه/مدل بررسی و نمایش داده شوند. [OpenAI Data Controls](https://developers.openai.com/api/docs/guides/your-data) [2](https://ai.google.dev/gemini-api/docs/zdr)
- **اعتبار و ایزولاسیون.** TLS، auth کوتاه‌عمر برای اپ، کلیدهای عرضه‌کننده فقط در secret manager و با کلید/سقف جدا برای هر محیط و قابلیت. `tenantId` از نشست، نه از درخواست؛ همهٔ queryهای job/stream با همان scope؛ idempotency، rate limit، سقف رسانه و هزینه، و اجازهٔ egress فقط به میزبان‌های ثابت آداپتر. کلید شخصی مسیر اختیاری موجود فقط با Keystore محلی، نه انتقال بی‌خبر به گیت‌وی. عدم export کامپوننت‌های داخلی، URI grants کم‌دامنه، عدم دسترسی شبکه برای قرارداد اجرایی `CommandPolicy`؛ گیت‌وی endpoint اجرای فرمان ندارد. revoke ورود و رضایت فوراً استفادهٔ جدید را ببندد؛ پاک‌سازی و سیاست نگه‌داری مستقل.
- **آزمون ایمنی:** NOOP برای prompt injection در OCR/متن مدل و ورودی ASSIST؛ تست دسترسی میان دو حساب، MIME/بایت نامعتبر، انصراف و خروج، قطع و وصل، replay، هزینه‌گیری تکراری، آفلاین بدون HTTP، لغو میکروفون در `onStop` و نداشتن handler. گزارش فقط کد وضعیت/زمان/ID تصادفی و مصرف بدون PII؛ نگه‌داری نمونهٔ صوت/تصویر صرفاً در آزمایش جدا با رضایت.

## ۷. نقشهٔ اجرا و معیار خروج هر مرحله

| مرحله / مسیر کار | اقدام | شرط خروج؛ توقف اگر برقرار نیست |
|---|---|---|
| **A · زیرساخت مشترک** — Android + backend | `RouteCatalog`، حساب مدیریت‌شده، scope و هزینه، مدل‌های قراردادی fixture؛ ثبت خط مبنای ۰٫۹. | انتخاب مدل و ذخیرهٔ ترجیح بدون wizard؛ مجوز از مدل به مدل منتقل نشود؛ بدون انتشار پولی تا حساب/منطقه/تعرفه و داده تأیید شوند. |
| **B · اول استودیوی تصویر** — Android + تصویر | رندر استودیو Sunburst و Nano Banana Pro؛ مرجع، ماسک/نسخه، مقایسهٔ اختیاری، متن فارسی و خروجی اصلی. | آزمون مستقیم/fixture برای هر API و ابعاد، سنجهٔ ۱۲۰ نمونه، ۰ ارسال تکراری در آزمون retry، عدم OOM و حفظ خروجی/اصل در گوشی واقعی. مسیر ناسازگار غیرفعال بماند. |
| **C · صدا و گفتگو، موازی پشت feature flag** — گفتار + UX | Azure `fa-IR`، استریم امن، گزینش صدا، transcript قابل ویرایش، صوت پاسخ، A/B روی موتورهای مجاز. | پذیرش WER/کیفیت/تأخیر، رفتار شفاف قطع شبکه، اجازهٔ صفر برای فرمان از متن مدل، آزمون اشتباه عدد و barge-in روی سخت‌افزار. |
| **D · فرمان بومی، ابتدا بدون وابستگی به C** — Android + test | `CommandPolicy`، سنجش slot، Intent/URI محدود، پیش‌نمایش و تأیید؛ سپس اتصال **نوبت نهایی** C به draft. | صفر اجرای ناخواسته در منفی‌ها؛ تست فیزیکی دستگاه/ساعت/تقویم/فایل/فلش، عدم ادعای دسترسی ناموجود. روشن‌شدن مسیرهای صوتی فقط بعد از قبولی C و D. |
| **E · پایلوت و انتشار** — مسئول انتشار | پایلوت با حساب‌های تست مجاز، هزینهٔ واقعی و مقایسهٔ کیفیت؛ rollout محدود، قطع سراسری هر route بدون آپدیت APK. | CI ماژول‌ها + همان APK امضاشده، آفلاین‌بودن حفظ شود، گزارش p50/p95 و کیفیت/خروجیِ حساب واقعی و دستگاه واقعی. اگر موتور قطع شد، فقط کارت خودش متوقف شود؛ نه سوییچ بی‌خبر. |

**ابزارهای اجرای پروژه:** از JUnit، fixtureهای OkHttp، Compose instrumentation و GitHub Actions موجود استفاده شود؛ Ktor test host/PostgreSQL آزمون ایزولاسیون گیت‌وی، OpenTelemetry فقط برای متریک‌های بدون محتوا، و Android Macrobenchmark/Perfetto برای اندازه‌گیری روی گوشی. SDK رسمی Speech در worker سرور کافی است؛ برای یک قابلیت چند SDK موبایل، موتور اتوماسیون ناشناس یا فریم‌ورک agent در APK نصب نشود. نسخه‌های پایدار، قفل وابستگی، بررسی مجوز/CVE و بودجهٔ نصب/حافظه شرط افزودن ابزارند.

**حد شواهد این طرح:** معماری و قراردادهای عمومی بررسی شده‌اند؛ هیچ حساب تجاری، کیفیت زندهٔ تصویر/گفتار، latency فیزیکی یا دسترسی منطقه‌ای به‌وسیلهٔ این سند تأیید نشده است. شماره‌ها دروازهٔ آزمون‌اند. مراحل بالا تغییری در APK ۰٫۹ ایجاد نمی‌کنند.
